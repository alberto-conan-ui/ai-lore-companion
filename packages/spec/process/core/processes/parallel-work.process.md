# parallel-work

The full life of a second work stream: carve it out, work it, land it (or let it
go). Run the opening steps from home; the middle happens in the child's own
sessions; the close comes back to home.

## When to run

- A second stream wants to proceed while home is busy, on a **disjoint** area — the
  claim conversation is the honest test: if you cannot cut disjoint claims, the
  work is not parallel, it is contended; sequence it instead.

## The steps

1. **`spawn-track`** *(from home)* — name, disjoint claim, focus pointer. The child
   exists unmounted.
2. **`mount-track`** *(usually a different session)* — attach, chain-walk, work.
   The child's sessions proceed normally: work, [`ack`](../verbs/acknowledgement/ack.verb.md)
   / ack-and-continue on the child's branches, close-session between sittings —
   the track outlives its sessions.
3. **`ack`** *(on the child, as its work completes)* — the child ends clean;
   judgement: land or discard?
4. **`merge-track`** *(land)* or **`abandon-track`** *(discard — auto-acked, twice
   confirmed)* — either way the branches go and home is whole again.
5. **`save-point`** *(offered when the last child closes)* — the consolidation
   moment merge unlocked; often the natural coda.

## Done looks like

No open child tracks; home's tree carries (or consciously discarded) the stream's
work; the accumulator tells the whole cross-branch story; a milestone sealed if the
moment deserved it.
