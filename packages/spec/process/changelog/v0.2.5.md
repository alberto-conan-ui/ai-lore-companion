# v0.2.5 — Process Refinements

**Date:** 2026-03-31

**Summary:** Internal release. Formalises append-forward and reconciliation as explicit operations, extracts them into their own document, and refines the memory model to clarify AT-is-intention (AT holds intention and gates, never design knowledge — all knowledge lives in KT from day one). Strips SDLC-specific naming from core files in preparation for the plugin architecture.

**Status:** Released (internal — external consumers see these changes in v0.3).

---

## Changes

### Append-forward and reconciliation extracted

Append-forward and reconciliation were implicit conventions scattered across principles.md, operating-rules.md, and memory.md. Now extracted into `process/updating-trees.md` as peer operations with explicit mechanics:

- **Append-forward** — default for all tree updates. New artifacts, never edits to existing ones.
- **Reconciliation** — controlled exception in Reflecting mode with Human Lead approval. Trees reshaped, journal documents the transformation.

**Files changed:** `process/updating-trees.md` (new), `process/principles.md` (summary with pointer), `roles/operating-rules.md` (summary with pointer), `process/memory.md` (AT section updated).

### AT-is-intention principle

The AT holds intention, status, and gates — never design knowledge, analysis, or context documents. All knowledge lives in the KT from day one, referenced from the AT via pointers. This keeps the AT cheap to reshape during reconciliation and ensures knowledge survives action archival.

**Files changed:** `process/memory.md` (AT section rewritten), `process/action-tree.md` (AT role clarified).

### SDLC-specific naming removed from core

Core files no longer reference SDLC-specific node types (goal, phase, step, task) or stance names (Architect, Tech Lead). Core defines containers, leaves, and archetypes. Domain-specific vocabulary belongs to plugins.

**Files changed:** `process/conventions.md`, `process/action-tree.md`, `process/memory.md`.

---

## Migration Steps (v0.2.2 → v0.2.5)

### Structural changes

1. **No structural migration required.** v0.2.5 is a documentation refinement — no folder structure changes, no file renames. The changes take effect when the methodology repo is updated.

### Behavioral changes

2. **AT knowledge audit.** If your AT nodes contain design knowledge, analysis, or context documents (not just intention and gates), consider migrating that content to the KT. This is not mandatory but aligns with the AT-is-intention principle.

3. **Reconciliation awareness.** Reconciliation is now a formal operation. If you reshape AT/KT outside of Reflecting mode without journal documentation, that's now explicitly against the process. No migration action needed — just awareness.
