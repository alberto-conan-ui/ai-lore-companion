# v0.2.7 — Core Process Documentation

**Date:** 2026-04-06

**Summary:** Internal release. Rewrites the core process documentation for the focus-based workflow model. Status becomes a first-class entry point (not buried in the AT). Focus files with gates replace the assumption that every project uses the action tree. The AT becomes optional infrastructure. Knowledge tree gains the three-branch structure (curated, notepad, payload). Stances are reframed as plugin-composed archetypes.

**Status:** Released (internal — external consumers see these changes in v0.3).

---

## Changes

### Status as first-class entry point

Status moves from `action-tree/status.md` to `status/status.md` — its own folder, above the memory layers. Status is the front door to the project, not an AT artifact. The `status/` folder also holds `focus/` for persistent focus files.

**Files changed:** `process/memory.md` (status section rewritten), `process/workflow.md` (status references), `bootstrap/README.md` (folder structure, skeletons).

### Focus-based workflow

The workflow is built around **focus** — a plain statement of intent with a gate, a mode, and a persistent file. Focuses stack for interrupts, archive on completion. The AT is no longer assumed — it's optional infrastructure for when a focus needs tracked decomposition.

New file: `process/focus.md` — defines focus files, gates, lifecycle, and rules.

**Files changed:** `process/focus.md` (new), `process/workflow.md` (rewritten around focus), `process/memory.md` (focus references).

### AT as optional infrastructure

The action tree is no longer mandatory. Simple focuses don't need decomposition. The AT earns its place when work needs tracked stages spanning sessions. Core AT mechanics (containers, leaves, gates) are preserved; domain-specific node types are delegated to plugins via a slot.

**Files changed:** `process/action-tree.md` (reframed as optional, slot added), `process/workflow.md` (AT section).

### KT three-branch structure

The knowledge tree gains a defined structure with three branches:

- **Curated** — durable, structured insights (replaces the flat topic folders at KT root)
- **Notepad** — unchanged from v0.2.2
- **Payload** — product description, structure defined by the plugin

**Files changed:** `process/knowledge-tree.md` (rewritten with three branches, slot for payload), `process/memory.md` (KT section), `bootstrap/README.md` (folder structure).

### Stances as plugin-composed archetypes

Core defines three archetypes (Auditor, Strategist, Builder). Plugins compose these into domain-specific stances. The "Without a Plugin" state is removed — every project must declare a plugin.

**Files changed:** `process/roles.md` (rewritten with archetypes and slot), `process/plugins.md` (mandatory plugin rule).

### Token efficiency as architectural goal

New section in principles.md documenting how structural conventions (indexes as loading hints, curated knowledge, hierarchy discipline, reference headers) are designed for AI token efficiency. The compound curve is expressed in tokens.

**Files changed:** `process/principles.md` (new section), `process/conventions.md` (hierarchy discipline).

### Core-as-infrastructure principle

Formalised: the journal is mandatory, the AT and KT are available infrastructure. The process scales with the work — use what earns its keep.

**Files changed:** `process/principles.md` (new section).

## Migration Steps (v0.2.5 → v0.2.7)

### Structural changes

1. **Create status folder.** Create `status/` and `status/focus/` and `status/focus/archive/` inside the memory folder.

2. **Move status.md.** Move `action-tree/status.md` → `status/status.md`. Update any references in `action-tree.index.md` and `ai_readme.md` that point to the old location.

3. **Create focus files.** If there's active work, create a focus file in `status/focus/` for each item on the active stack. Each focus file needs: gate, mode, state pointer, and context links. See `process/focus.md` for the format.

4. **Restructure KT branches.** Wrap existing topic folders under `curated/`. Create `curated/curated.index.md`. Create `payload/` with `payload.index.md`. Notepad stays where it is. Update `knowledge-tree.index.md` to point to the three branches.

5. **Update status.md format.** Remove "SDLC version" field (version now lives in workspace.yaml). Add mode field. Update to match the v0.3 skeleton format.

### Behavioral changes

6. **Focus-first workflow.** Work is now organized around focuses, not AT actions. The AI orients from status → focus file → (optionally AT). Old habit of starting from AT root index should shift to starting from status.md.

7. **AT is optional.** If your project's current work doesn't need tracked decomposition, the AT can remain but isn't the entry point. New work starts with a focus, not an AT goal.
