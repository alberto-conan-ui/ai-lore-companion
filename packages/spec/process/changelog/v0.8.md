## RC notes

v0.8 is RC-gated per `blueprint/processes/release.process.md`. The acceptance gate runs on a **disposable subject** (F9): a checkout of this project at the `v0.7` tags — Payload, Memory, and the vendored v0.7 `process/` — migrated by a fresh session that has only the playbook, then reopened by a second fresh session that must orient and exercise the load-bearing verbs (F10).

**rc1 (2026-09-07)** — cut after s4 (contracts) and s5 (sharing + lifecycle + F12) closed on the `v0.8` branch. **Failed the gate at step 2**, in a fresh session running the playbook literally:

- **F-1 (blocking)** — `ai-lore.py migrate` refused every v0.7 project with *"not inside an AI-Lore project"*: its project detector only recognised the v0.8 manifest location (`memory/workspace.yaml`), never the v0.7 one (`<lore>/workspace.yaml`) — the tool could not find the very shape it exists to migrate. Same defect, second hazard: `--project` was fed through an upward-walking detector, so a v0.7 copy nested under a v0.8 project would have silently resolved to the ancestor. *Fix:* the detector accepts both manifest locations; an explicit `--project` is taken as the root and never walked; `migrate` validates the root directly. (Also folded in: a cosmetic index-spacing fix in the knowledge-tree → notepad step.)

**rc2 (2026-09-07)** — F-1 fixed on the release branch; gate re-cut against a fresh copy of the same disposable subject (F9 makes the re-run literal, not by inspection). **Migration ran as written, end to end.** Three non-blocking findings: the F7 move left `memory.index.md`'s Manifest reference pointing at the old location; the step-6 payload list omitted `CLAUDE.md`; the Verify command lacked `--project`. Not promoted — a tool change is a new candidate.

**rc3 (2026-09-07)** — the three fixed (tool repoints the reference; `check` now also scans the live Memory surfaces; playbook wording); full gate re-run on a fresh subject. **Reopen (F10) passed** — fresh session through the installed binding oriented with zero missing files; `add-note`, `ack-and-continue` (row appended), `run-process` resolution, and the journal guard all behaved. **Migration held by one blocking finding** the widened `check` surfaced: `migrate` deleted the vendored tree without remapping Memory links that pointed into it (`save-points.index.md` → `../../process/verbs/save-point.md`), so Verify could never print `OK`.

**rc4 (2026-09-07)** — `migrate` now remaps every Memory link into the vendored tree (journal excepted) to its v0.8 target, v0.7 verb names mapped; gate re-run in full on a fresh subject. **Passed, zero findings**: the playbook ran as written end to end and Verify printed `OK`; the fresh reopen through the installed binding oriented with no missing files; `add-note`, `ack-and-continue` (row appended), `run-process` resolution, and the journal guard's deny all behaved. Four candidates for one release is the gate working: every finding was a real defect a downstream user would have hit in a fresh session (rc1: the tool could not see a v0.7 project; rc3: links into the deleted vendored tree).

## Summary

The **verb-discipline** release. Where v0.7 disciplined the *shape of status*, v0.8
disciplines the *act of writing*: **every write is confirmed to a verb; nothing
writes unchosen** — the golden rule, now a contract every verb cites. To make the
rule total rather than aspirational, the verb layer is regenerated as **entity
families** (52 intent-named verbs in nine families, each an encyclopedia for its
operation), so that completeness is auditable per noun instead of hidden inside one
generic `write-lore`.

Three structural moves ride with it. **AI-Lore dissolves into its own artifact
system**: the out-of-the-box methodology no longer lives in a vendored `process/`
tree but in `blueprint/{verbs,processes,contracts,tooling}/core/`, never edited in
place, customized by **shadowing by name**, and shareable through an ordered
**`parents:`** list — AI-Lore becomes an upstream distribution a project configures,
with core as the implicit root of every project's parent chain. **Contracts become
first-class**: four core contracts (`golden-rule`, `ack-pairing`,
`core-containment`, `journal-append-forward`), stated in the floor, cited at the
point of action, reinforced by engine hooks where mechanically checkable. And the
**save-points ledger gains an open accumulator**: every ack-family commit appends an
annotated row (verb, track, branch, payload hash; the row's lore commit
self-identifying) so any consumer resolves every cross-repo pair from one file —
`save-point` seals it.

The bootstrap shrinks to a **floor** (`ai_readme.md`: golden rule, resolution chain,
opening steps, the un-overridable four — `add-verb` / `add-process` /
`add-contract` / `run-process`). A **process layer** carries the journeys the cards
cannot (`start-work`, `parallel-work`, `recover-session`, `groom`, `close-out`),
driven by `run-process` under per-write confirmation. **Grooming verbs** — a new,
interrogative, home-only kind — hunt what lingers (`review-focus-tree`,
`integrate-notepad`, `review-backlog`, `review-mirror`, `review-references`). The
**knowledge tree is retired**; the **notepad** survives as a top-level buffer that is
never a destination. And the mechanical halves of `init` / `install` / `upgrade`
ship as one stdlib script, `ai-lore.py`, in `tooling/core/`.

## Changes

### The golden rule, and contracts as artifacts

**Every write is confirmed to a verb.** Reads are free; every write names its verb
and the Human Lead confirms (a standing instruction naming a verb and cadence
counts). No exempt surface — scratch included. No inference: the session proposes,
the Human Lead chooses. Stated first in the floor, carried as the `golden-rule`
contract, cited by every verb (step 1 of every operation is the confirmation).

**`blueprint/contracts/core/`** ships four: `golden-rule` (judgement), `ack-pairing`
(checkable — every ack a paired, payload-first, ledgered commit), `core-containment`
(checkable — floor + blueprint, nothing else, core never edited in place),
`journal-append-forward` (checkable — journal entries never edited). Contracts are
defined by inviolability, not hook-ability; enforcement is layered — stated → cited →
reinforced. Contracts **accumulate** across the resolution chain.

### Entity-verb families

The v0.7 verb set (`write-lore`, `grow`, `advance`, `archive`, `mount`, `spawn`,
`merge`, `abandon`, `ack`, `ack-and-continue`, `save-point`, `publish`, `init`,
`install`, `upgrade`, plus the bookends) regenerates as **52 verbs in nine
families**, each folder holding one **family context doc** and lean **cards**
(*When to invoke · The operation · Refusals · Related*): status-tree (11), buffers
(4), blueprint authoring (15, incl. `run-process`), payload (1 — `update-payload`,
the floor for Payload writes), tracks (6), acknowledgement (3), outward (7),
lifecycle (4), bookends (2). Kebab-case names after the intent: `add-new-focus`,
`complete-stage`, `mount-track`, `integrate-notepad`. Uniform `add-` / `update-` /
`retire-` grammar across blueprint entities. `write-lore` dissolves into the
families — totality by enumeration, not vagueness. See
`blueprint/verbs/core/verbs.index.md` for the map and the v0.7 → v0.8 name mapping in
[`migration-from-v0.7.md`](../migration-from-v0.7.md).

### Core dissolves into blueprint; shadowing; parents

- **`core/` per branch.** The OOB set lives in `blueprint/verbs/core/`,
  `processes/core/`, `contracts/core/`, `tooling/core/` — placed by `init`, replaced
  wholesale by `upgrade`, never edited in place. The vendored `<lore>/process/` tree
  is gone; `workspace.yaml` moves into the Memory repo (F7).
- **Shadow by name.** A same-named artifact outside `core/` wins. Resolution: core <
  parents (declaration order) < local, by name, lowest wins; contracts accumulate.
- **`parents:`** — an ordered list of AI-Lore project roots in `workspace.yaml`;
  their `blueprint/` artifacts become invocable here. `add-parent` / `remove-parent`
  walk the delta with the Human Lead. Parents form a DAG; core is its implicit root.
- **The un-overridable floor**: the bootstrap plus `add-verb` / `add-process` /
  `add-contract` / `run-process`.
- **`upgrade` is a merge decision made small**: core replaced wholesale, then each
  local shadow re-validated against the new core (retire / amend / keep) — minutes,
  because every shadow carries its one-line what/why.

### The ack ledger

`save-points/next.save-point.md` is always open. `ack`, `ack-and-continue`,
`save-point`, `close-session`'s closing commit, and `abandon-track`'s auto-ack each
append a row — date · verb · track · branch · payload hash · summary — payload
committed first so the row pins its hash, lore second so the row's commit is
self-identifying. `save-point` seals the accumulator into the dated entry (the
milestone's story is its rows) and opens a fresh one. Cross-repo, cross-branch
correlation by data.

### Processes and `run-process`

Five core processes (`groom`, `close-out`, `start-work`, `parallel-work`,
`recover-session`) carry the when-to-run-which-verb knowledge. `run-process`
resolves a process by name, pre-checks every step, and walks it — each step's verb
confirmed in full; a refusing step halts the run honestly.

### Grooming verbs, notepad, knowledge tree retired

Grooming verbs are interrogative and home-only: they read, find what lingers,
interview the Human Lead, and execute accepted outcomes through the lifecycle verbs
— never bypassing them. The **notepad** (`memory/notepad/`) is the knowledge inbox,
writable from light tracks (`add-note`), drained by `integrate-notepad` into
contract / mirror / tooling / backlog — or killed. The **knowledge tree** is retired;
its files migrate into the notepad for routing.

### Tooling: `ai-lore.py`

`blueprint/tooling/core/ai-lore.py` (stdlib Python 3): `resolve`, `check`,
`install claude|gemini`, `upgrade --from`, `init`, `migrate` (0.7 → 0.8). The Claude
binding projects card + family context into one skill with links rewritten (F11),
enforces `journal-append-forward` with a PreToolUse deny, and reinforces the golden
rule with a PostToolUse reminder. `check` is the core-containment gatekeeper.

### Leftovers closed

F6 (branches record-authoritative; `trunk` is role-language), F7 (`workspace.yaml`
in the Memory repo), F9 (the RC gate runs on a disposable subject), F10 (the gate
reopens a fresh session), F11 (projected links resolve), F12 (`init` settles the Lore
remote; this project's Memory now has one). F5 stays open by decision — resolved by
overdue Done calls, not by an enum.

## Migration

See [`migration-from-v0.7.md`](../migration-from-v0.7.md). Mostly mechanical
(`ai-lore.py migrate`): manifest into Memory, core placed, vendored tree removed,

untouched. Verb names change — the mapping table is in the playbook.
