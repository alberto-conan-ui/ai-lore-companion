## Summary

A **process polish** patch. Five tweaks shaken out by using v0.6: the ack verb gets decoupled from close-session (with a new lightweight sibling for mid-execution commits), focuses gain a `claim` field so home's claim is focus-derived rather than implicit-everything, the Gemini engine gets a real binding section (Claude-only until now), chat posture gains a narrow **marginalia** exemption so HL-initiated housekeeping (frontmatter edits, link repair, typo fixes, index entries) no longer requires redialing out of chat, and the always-present track is **renamed from `master` to `home`** to remove the overload with git's old default branch name and the double-naming with the `trunk` branch it sits on.

The organising principle: *each verb does its own job; no verb prompts the user about another verb's responsibilities*. The marginalia carve-out is the same principle reapplied — chat's job is conversation, but housekeeping is not composition, so it stays within chat. The home rename is the same principle taken to vocabulary — the track's name and the git branch it sits on no longer compete for the same word.

## Changes

### Ack / close-session decoupling

**`ack` no longer offers `close-session` first.** The unconditional "run close-session first?" prompt added in session 74 was right for *closing* acks but pure noise for *mid-execution* acks. ack now commits without any close-session interaction — a deliberate pause-point commit with an HL-confirmed, area-grouped message.

**New verb — [`ack-and-continue`](../verbs/ack-and-continue.md).** A lightweight sibling for mid-execution chunking. Same commit shape as ack; minimal message ceremony; session continues immediately after the commit. Use when the work has reached a clean chunk and the next step is to keep going, not to pause for review.

**`close-session` commits its own writes.** Previously close-session wrote the journal and status entries but left committing to a separate ack invocation, which produced a "dirty right after save-point" friction. Now close-session writes the journal and status, then solicits an HL-confirmed closing commit that bundles drift + the journal/status writes in one shot. The "session never self-acks" rule still holds — the HL confirms the message.

**`save-point` / `merge` / `abandon` are explicitly decoupled** from close-session in their relationship sections. None of the committing verbs prompt about close-session; close-session handles its own commit at session end. The previous coupling (ack offering close-session) is removed because most acks have nothing to do with closing.

### Focus carries `claim`

**Focus files gain an optional `claim` field** (path prefixes — Payload and Memory areas the focus owns when active on a track). Set when the focus is created: the session proposes a claim from context (title, area, references); the Human Lead confirms or edits before the focus file is written. The proposal is a starting point, not a commitment — claim can be edited on the focus (the persistent default) or polished on home's track record (the working override).

**Home's claim is now focus-derived** when the active focus carries `claim`. At home mount, if home's claim is unset, it is seeded from `focus.claim`; if already set from a prior session's polish, it is preserved. Focus switch re-seeds home's claim.

**Back-compat preserved.** A focus without `claim` keeps home in implicit-everything mode (v0.5.1 / v0.6 behavior). Existing v0.6 projects do not need to backfill — adding `claim` to a focus is opt-in, used when parallelism on home is anticipated.

### Gemini binding

**`bindings.md` gains a `## Binding: Gemini` section** parallel to Claude's. Structure: `GEMINI.md` handshake (delimited block, auto-loaded via Gemini's hierarchical context discovery); verbs project to TOML slash commands at `.gemini/commands/ai-lore-<verb>.toml` using `@file` injection from the canonical verb file (thin pointer, no stale projection); `SessionStart` and `SessionEnd` hooks in `.gemini/settings.json` emit JSON with `additionalContext` instructions for the bookends.

**SessionEnd asymmetry called out honestly — and folded into the Claude section too.** Gemini's docs declare SessionEnd advisory ("doesn't wait, ignores flow-control fields"); the Claude binding section had implied SessionEnd reinforced close-session, which is also incorrect. Both binding sections now describe the same asymmetry: SessionStart genuinely reinforces orient (injection lands as first turn); SessionEnd is telemetry-grade — close-session works because the model invokes it proactively, driven by the methodology loaded at session start, not by the hook.

**`install.md` step 3** lists both Claude and Gemini explicitly. The engine-agnostic language is preserved; the binding sections in `bindings.md` are the source of truth.

**No `/plan` collision for Gemini** — Gemini CLI has no built-in plan mode. The Gemini handshake block is one line shorter than Claude's.

### Chat marginalia carve-out

**Chat is no longer absolutely write-blocked on Memory.** The posture still gates substantive writes — composition, prose, restructuring, new content — but defines a narrow allow-list of **marginalia** operations that any HL-initiated chat may execute: frontmatter edits (references, `updated:`, status, title), link repair where the file's meaning is unchanged, single-token typo or punctuation fixes, index entries (adding sibling/child lines in an `.index.md`). The litmus: *if removing the change wouldn't shift what the file means to a future reader, it's marginalia*.

**Marginalia is Memory-only.** The Payload's read-only rule under chat (and plan, and reshape) remains absolute — a Payload typo fix still requires `execute`.

**Marginalia is Human-Lead-initiated.** The session does not decide to write marginalia on its own; chat means converse first. The HL reaches for marginalia explicitly while chatting — *"while we're here, fix that stale reference"* — and the session executes the narrow write through `write-lore`.

**Marginalia goes through `write-lore`.** Placement, schema, and claim enforcement all apply. The chat exemption permits the write under chat posture; it does not bypass `write-lore`'s guarantees. Trackless chat marginalia triggers `mount` the same as any other write (auto-master if free).

Spec lands in [`verbs/chat.md`](../verbs/chat.md), with cross-refs in [`status.md`](../status.md#posture), [`verbs/write-lore.md`](../verbs/write-lore.md), and [`verbs/verbs.index.md`](../verbs/verbs.index.md).

### `master` → `home` rename

**The always-present track is renamed from `master` to `home`.** The role is unchanged: always present, sits on `trunk`, never merged or abandoned, the only track save-points run on, what child tracks branch from. Only the name changes.

Two reasons compounded:

- **Git collision in the reader's head.** Git's old default branch was `master`. Readers pattern-match "master track" to "the master branch" — even though in v0.6 the master track literally sits on `trunk`, not on `master`. The vocabulary fought the reader every time.
- **Internal redundancy.** v0.6 explicitly states *"there is no separate master branch; master is trunk."* Two words for one thing. The home rename collapses the redundancy: home is the track's role, trunk is the branch name, they no longer compete.

**File rename — `tracks/master.md` → `tracks/home.track.md`.** This also fixes a latent inconsistency: the methodology's tree discipline (memory.md) says every file is `[name].[type].md`, but master was the lone exception using a bare `master.md`. Aligning to `home.track.md` brings the always-present track in line with child tracks (`<name>.track.md`) and every other typed file.

**Branch arrangement unchanged.** Home sits on `trunk` — same as master did. Child tracks sit on `track/<name>` — unchanged. Only the track name and the file name change.

**Spec sweep landed in:** `tracks.md` (heavily), `git.md`, `status.md`, `memory.md`, `project-structure.md`, `ai_readme.md`, and every verb file that referenced the track by name (`mount`, `merge`, `abandon`, `ack`, `ack-and-continue`, `save-point`, `close-session`, `orient`, `chat`, `plan`, `reshape`, `execute`, `publish`, `init`, `write-lore`, `verbs.index.md`).

## Migration

**One Memory edit required** — rename `tracks/master.md` → `tracks/home.track.md`, update the `name` field inside, and update the open-tracks list in `status.index.md`. Everything else is spec-additive with back-compat preserved:

- `ack` losing the close-session offer is a behavior change inside the verb; re-running `install-claude` after upgrading projects the new verb text into the skill.
- `ack-and-continue` is a new optional verb; existing projects ignore it until invoked.
- `close-session` committing its own writes is a behavior change in the bookend; re-running `install-claude` re-projects.
- Focus `claim` is optional; existing focuses without `claim` keep working unchanged.
- Gemini binding is additive; Claude projects are unaffected.
- Chat marginalia is additive; behaviour under non-chat postures is unchanged.

Full playbook for the home rename and the install re-runs lives in [`migration-from-v0.6.md`](../migration-from-v0.6.md). Projects on v0.6 invoke `upgrade` against that playbook.

Projects on v0.5.1 or earlier chain through `migration-from-v0.5.1.md` first (which lands at v0.6 — still using master), then `migration-from-v0.6.md`. The `upgrade` verb runs one hop at a time.
