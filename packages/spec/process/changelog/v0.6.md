## Summary

A **parallelism pillar.** v0.5.1 and every version before it assumed one session at a time. `status.index.md` carried the active focus, posture, and dials as if status were a session record. Two sessions in the same project would clobber each other; running plan in one tab while execute ran in another was not supported.

v0.6 introduces **tracks** — persistent workspaces that wrap a branch and carry their own posture, dials, and focus pointer. Sessions mount tracks (one session per track, one track per session); master is always present and sits on trunk; child tracks branch from master and merge back. The single-session common case is preserved exactly: master is auto-mounted on first write, no prompt, no branch operation, behaviour identical to v0.5.1. Parallelism is the option, not the default.

The organising principle: *the session is the runner; the track is the workspace.*

## Changes

**Pillar set grows from five to seven.** Two new pillars join the methodology — [`tracks.md`](../tracks.md) and [`git.md`](../git.md). Tracks pulls the workspace primitive (track, master vs children, mounting, claims, sessions) out of `status.md`, returning status to a dashboard-sized pillar (registry + focus + dials + posture + presets + redial). Git pulls the two-repos arrangement out of `project-structure.md` and the drift signal mechanics out of `memory.md`, centralising the git contract — `.gitignore` rules, branches, the lore-repo `.git/` location wart, vendored `process/` untracking, `publish/` in no repo, per-track drift, the explicit `git -C` discipline. Every session loads all seven pillars at orient; `ai_readme.md` lists them in order.

**New term — Track.** A seventh foundational term joins Project / Payload / Lore / Memory / Track / References / Publish. A track is a persistent workspace within Memory — a branch + claim + posture + dials + focus pointer. Sessions mount tracks (one per track). Master always exists; child tracks branch from master and merge back. Lives at `<memory>/tracks/`.

**New Memory component — `tracks/`.** Sixth component joins Journal / Blueprint / Save-points / Action tree / Knowledge tree. Tracks is required (master is always present). Track records are typed files (`<name>.track.md`) carrying the branch name, the claim, the posture, the dials, and an optional focus pointer.

**Status restructured as a registry.** `status.index.md` no longer carries `active_focus`, `posture`, or `dials` in its frontmatter — those move onto track records. Status becomes a summary registry: open-tracks list, save-points pointer, blueprint pointer, journal trail (newest-first across all tracks), per-track drift summary, and pointers to subfolders. The focus stack is **derived** from open tracks (which focuses have tracks pointing at them) — no longer stored as its own field.

**Three new verbs — `mount`, `merge`, `abandon`.** These form a new sixth group on the verbs index, named **Tracks**.

- **[`mount`](../verbs/mount.md)** — attach a session to a track. Auto-mounts master silently when master is unmounted and a write is requested; HL-prompted on contention (master taken, child tracks available, or new-child needed). Mount fires implicitly on first write (any verb that writes); it can also be invoked explicitly up front.
- **[`merge`](../verbs/merge.md)** — land a child track's work onto master. HL-invoked; sessions never self-merge. Merges both repos in parallel on the track's branches, removes the track record, deletes the branch.
- **[`abandon`](../verbs/abandon.md)** — discard a child track. HL-invoked with a confirmation prompt; auto-acks any pending work first so the commits survive in git's object store (recoverable); then deletes the branch and removes the record.

**Save-point becomes the consolidation primitive.** Save-points are master-only and refuse if any child track is open. To take a save-point, every in-flight child track must be merged or abandoned first. This makes save-points represent a coherent project state — one trunk, no in-flight branches.

**Ack adapts to tracks.** Ack commits on the mounted track's branches (`trunk` for master, `track/<name>` for a child). The two-repos-commit-together rule is unchanged; the branches are per-track.

**Write-lore enforces the claim at every write.** A path outside the mounted track's claim (with `*.index.md` files and `status.index.md` as a shared carve-out) is refused. Disjointness across all open tracks is verified at track creation and at every claim-change.

**Posture verbs write to the mounted track.** `chat` / `plan` / `reshape` / `execute` write to the mounted track's record rather than to `status.index.md`. `chat` while trackless is a no-op (trackless is already read-only). Other posture verbs trigger a mount (auto-master if free) on first invocation while trackless.

**Redial writes to the mounted track.** Dials live on the track record. While trackless, redial is **volatile** — the in-conversation register changes but nothing persists; the next mount picks up the track's saved dials.

**Trackless sessions leave no trace.** A session that never mounts a track writes no journal entry and updates nothing in Memory at close. Trackless is the ephemeral read-only mode for consulting the project; the audit trail is the record of work that touched the project.

**Orient is track-aware.** When only master is open (or no other tracks exist), orient assumes master/trackless and walks the full focus chain exactly as v0.5.1 does — single-session projects pay no parallelism tax at orient. When other tracks are open, orient defers the chain walk and asks the Human Lead at session start whether to mount.

**Close-session per session, no coordination.** Each session closes independently — writes its own journal entry (if mounted), surfaces its own track's drift, unmounts. Consolidation across all tracks happens only at save-point.

**Publish becomes master-only.** Publishing ships the canonical state; child tracks do not publish. Invoking publish from a child track is refused — the Human Lead closes the session and reopens on master to publish.

**Init creates `tracks/master.md` at project creation.** A fresh v0.6 project starts with master populated: `posture: execute` (the default), default dials, no active focus, branch `trunk`.

**Journal schema adds `track`.** Every journal entry's frontmatter carries a `track` field naming the track the session mounted. The field is backfilled to `master` on existing entries by the migration.

**Branch naming.** A child track's branch is `track/<name>` on both repos. Master sits on `trunk`. The two repos branch and merge together as one unit, the same way ack and save-point already commit them together.

## Migration

Ships with [`migration-from-v0.5.1.md`](../migration-from-v0.5.1.md) at the methodology root, applied by the [`upgrade`](../verbs/upgrade.md) verb.

The migration is **Memory-only** — the Payload is untouched. Steps: preflight (refuse if either repo is dirty), bump `core_version` to `"0.6"`, re-place the methodology, create `tracks/master.md` from `status.index.md`'s state, restructure `status.index.md` into the registry shape, backfill journal frontmatter (`track: master` on every existing entry), commit.

Projects on v0.5 or earlier chain through `migration-from-v0.5.md` first, then this playbook. The `upgrade` verb runs one hop at a time.
