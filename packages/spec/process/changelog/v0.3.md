# v0.3 — Plugin Architecture

**Date:** 2026-04-06 (tag re-cut 2026-04-08 for hotfix — see below)

**Summary:** First external release since v0.2.2. Introduces the plugin architecture: domain-agnostic core with slots, domain plugins with joins. Every project declares a plugin in workspace.yaml. Plugins define stances, conventions, checkpoints, and KT payload structure. Core and plugins are independently versioned. Includes all changes from v0.2.5 (process refinements) and v0.2.7 (core process documentation). Renames `.ai-sdlc/` to `.ai-lore/`.

**Status:** Released.

---

## Changes

### Plugin architecture (slots and joins)

Core files declare **slots** — places where the core is deliberately abstract. Plugin files declare **joins** — which core file they attach to, the relationship type (addendum or substitution), and specific loading instructions.

New file: `process/plugins.md` — the full plugin model.

Five core files have slots: `roles.md`, `workflow.md`, `action-tree.md`, `conventions.md`, `knowledge-tree.md`.

### Mandatory plugin declaration

Every project must declare a plugin in `workspace.yaml`. A missing plugin is an error — the Auditor is invoked to diagnose and migrate. No "pluginless" state.

### Plugin manifest in workspace.yaml

`workspace.yaml` now includes:

```yaml
core_version: "0.3"
plugin: sdlc
plugin_version: "0.1"
plugin_readme: "methodology/process/plugins/sdlc/ai_readme.md"
```

Version fields for both core and plugin. The Auditor reads these to determine migration needs.

### Plugin session configuration

Each plugin has an `ai_readme.md` that provides the loading table, stance catalogue, and quick reference. The core `ai_readme.template.md` tells the AI to read `workspace.yaml` for the plugin, then read the plugin's session configuration.

### Independent versioning

Core and plugins are versioned independently. Each has its own changelog:

- Core: `process/changelog/`
- Per plugin: `process/plugins/<plugin>/changelog/`

The Auditor reads both changelogs to determine what needs migrating for a given project.

### Three shipped plugins

| Plugin | Domain | Stances | Version |
|---|---|---|---|
| SDLC | Software development | Architect, Tech Lead | 0.1 |
| spec | Methodology/process design | Editor, Strategist | 0.1 |
| TTRPG | Tabletop RPG campaigns | Game Master | 0.1 |

The **Auditor** is a core stance available to all plugins — it handles process health evaluation and version migration. It is not plugin-specific.

### Stance files in plugin folders

Each plugin's stance entry points now live under `process/plugins/<plugin>/roles/`. Core `roles/` contains only infrastructure files (`operating-rules.md`, `common.md`) and the Auditor stance.

### Anti-patterns removed

`process/anti-patterns.md` has been removed. The general anti-patterns (rubber stamp, amnesia sessions, stance bleed) are already covered by the principles and operating rules they derive from. Domain-specific anti-patterns belong in plugin documentation, not core.

### Naming: AI-SDLC → AI-Lore

The methodology is renamed from AI-SDLC to AI-Lore. The memory folder convention changes from `.ai-sdlc/` to `.ai-lore/`. "Lore" names the output — the compounding body of knowledge a project builds over time.

### Subsumes v0.2.5 and v0.2.7

All changes from v0.2.5 (process refinements, reconciliation, AT-is-intention) and v0.2.7 (focus-based workflow, status entry point, KT three branches, optional AT) are included. See those changelog entries for details.

### Hotfix (2026-04-08): plugin ai_readme.md files restored

The original v0.3 tag was missing the three plugin session config files (`process/plugins/sdlc/ai_readme.md`, `spec/ai_readme.md`, `ttrpg/ai_readme.md`) because `.gitignore` had a blanket `ai_readme.md` pattern that caught them in every directory. The pattern was changed to `/ai_readme.md` (root-only), the files were committed, and the v0.3 tag was moved to include the fix. If you cloned v0.3 before this date, fetch tags and pull.

## Migration Steps (v0.2.2 → v0.3)

This is the migration path for projects running v0.2.2 (the last released version before v0.3). It covers everything from v0.2.5, v0.2.7, and v0.3 in a single pass.

### Phase 1 — Structural (memory folder)

1. **Rename memory folder.** `.ai-sdlc/` → `.ai-lore/`. Update `.gitignore` if present.

2. **Create status folder.** Create `status/`, `status/focus/`, `status/focus/archive/` inside the memory folder.

3. **Move status.md.** Move `action-tree/status.md` → `status/status.md`. Remove the "SDLC version" field — version now lives in workspace.yaml.

4. **Create focus files.** For each item on the active stack, create a focus file in `status/focus/`:
   ```markdown
   # [Focus name]

   ## Gate
   - [Concrete criteria from the existing action's gate]

   ## Mode
   [Current mode from status.md]

   ## State
   [Pointer to journal handover or AT action]

   ## Context
   [Links to relevant KT nodes and AT goals]
   ```

5. **Restructure KT.** Create `curated/` with `curated.index.md`. Move existing topic folders into `curated/`. Create `payload/` with `payload.index.md`. Update `knowledge-tree.index.md` to point to three branches (curated, notepad, payload).

6. **Update AT root index.** Change the status.md reference from local to `../status/status.md`.

### Phase 2 — Manifest (workspace.yaml)

7. **Add version and plugin fields to workspace.yaml:**
   ```yaml
   core_version: "0.3"
   plugin: <chosen-plugin>
   plugin_version: "0.1"
   plugin_readme: "methodology/process/plugins/<chosen-plugin>/ai_readme.md"
   ```
   The human must choose which plugin fits the project. The Auditor should suggest based on the project's domain.

### Phase 3 — Entry point

8. **Regenerate ai_readme.md.** Copy from `{methodology}/bootstrap/ai_readme.template.md`. The old ai_readme.md references stale paths (action-tree/status.md) and missing concepts (plugins). Replace it entirely.

9. **Update status.md format.** Align with the v0.3 skeleton:
   ```markdown
   # <Project Name> — Status

   > Single source of truth. Every stance reads this first.

   | Field | Value |
   |---|---|
   | **Mode** | [current mode or —] |
   | **Active focus** | [focus name or Headless] |
   | **Last journal** | [link] |

   **Where we are:** [brief description]
   ```

### Phase 4 — Verification

10. **Verify all links.** Status.md → focus files → journal → AT/KT. All references should resolve. The AT root index should point to `../status/status.md`.

11. **Test session start.** Read `ai_readme.md` and follow the Session Start Protocol. The AI should: find the plugin in workspace.yaml → load core → load plugin → load stance → announce. Any broken link or missing file is a migration bug.

### Behavioral changes (no structural action needed)

12. **Mandatory plugin.** The project must have a plugin. No more operating with core archetypes directly.

13. **Focus-first workflow.** Orient from status → focus, not from AT root. AT is optional infrastructure.

14. **Independent versioning.** Version lives in workspace.yaml, not status.md. The Auditor checks workspace.yaml for migration decisions.
