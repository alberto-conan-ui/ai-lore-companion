## RC notes

v0.7 is the first **RC-gated** release (see `blueprint/processes/release.process.md`). The acceptance gate is the dogfood self-migration of `ai-sdlc` itself.

**rc1 (2026-06-19)** — migrated the source project `v0.5.1 → v0.7` (the source was three versions behind its stamp). Destination validated: a clean, orient-able v0.7 status tree, deep `focus → stage → phase` chain intact. But the migration could not be run *literally* — three playbook defects required mid-flight correction, so rc1 is not promotable:

- **F1** — the v0.7 playbook assumed its predecessor's structure (`tracks/home.track.md`) existed; a project behind its version stamp has no such file. *Fix:* the playbook now checks structural shape, not just `core_version`, and stops if behind.
- **F4** — the v0.5.1→v0.6 playbook said *backfill `track:` into all historical journals*, contradicting v0.7's *never edit journal history*. *Fix:* reconciled to append-forward — new entries only.
- **F8** — every playbook's Step 1 cloned `main`; wrong for the source project (candidate isn't on main) and for multi-hop (main is always latest). *Fix:* per-project sourcing — downstream from the release/RC tag, the source project from local `process/`, each hop from its own version.

The gate itself was hardened: Part B now requires the dogfood run *literally* (ideally a fresh session with only the playbook); any correction the runner must make is a **blocking finding**, not a fix.

**rc2 (2026-06-19)** — F1/F4/F8 fixed on the release branch; gate re-cut. Promotable pending the literal re-verify.

Open (deferred, do **not** block v0.7): the status enum has no clean state for "shipped long ago, awaiting an indefinitely-deferred Done call" (mapped `paused`); the spec hardcodes the home branch `trunk` while real projects use `main`; `workspace.yaml` (holding `core_version`) sits in no git repo.

## Summary

The **status tree** release — the largest Memory-shape change since v0.5. Earlier versions split the project's orientation in two: a status *registry* (`status/`) and a separate *action tree* (`action-tree/`) for decomposition, joined only by pointers. The two drifted independently — status pages bloated into narrative, decomposition branches lingered after they were done, indexes were stuffed with history and instructions. v0.7 merges them into **one status tree** with a forced, uniform shape, and makes that shape impossible to corrupt by hand.

The organising principle: *the shape is the discipline.* Three positional levels named by depth, every level a folder with a strict index, a registry file bounded by a fixed table, and structural mutation locked behind a small set of typed verbs — each removes a degree of freedom that, left open, produced the mess.

v0.7 also makes a sharp **subtraction**: **posture and dials are removed entirely** (chat/plan/reshape/execute, altitude/commitment, `redial`, presets — gone). What a session may touch is now governed by its **track type**, and tracks gain two lighter types alongside the full track. Several more changes ride along in the same anti-mess spirit: lazy methodology loading (load less, declare what you need), a `blueprint/tooling/` registry for owned scripts, a root-level `out/` catch-all for disposable writes, and a `status/backlog/` for pre-focus to-dos.

## Changes

### The status tree

**One tree at `memory/status/`, three positional levels — focus → stage → phase.** Depth *names* the level: a focus's children are stages, a stage's children are phases. At most three deep; you may stop early but never skip a level or rename one; every level that exists is a folder carrying a standard index. The old `action-tree/` component is retired — its role is now the lower levels of the status tree. The `at-node` type is replaced by `stage` and `phase`; `node_kind` is gone (position determines it).

### `status.stack.md` — the focus registry

**A new root-level file, the project's at-a-glance "what focuses exist and where each stands."** One line per focus (L1 only): **link + status + active-mark**, nothing else — no description (in the focus's file), no dates (in the journal), no notes. The status enum is fixed at **`draft` / `paused` / `in progress` / `done`** (review folds into `in progress`; the old done/achieved split collapses to `done`). The active-mark is **per-track** — it holds the track name working a focus, honouring v0.6 parallel tracks. It is a fixed table by design: a cell resists growing into a paragraph.

### Strict indexes, everywhere

**The old `status.index.md` narrative is destroyed.** Its content is redistributed: focus status → `status.stack.md`; the journal trail → the journal index (`journal/live/live.index.md`) as its single source; drift → derived at `orient`, stored nowhere; blueprint/save-point pointers → the root index's References. The status-tree root becomes an ordinary AI-Lore index — pure wiring, no exceptions. `memory.md` tree-discipline is hardened: an index carries pointers only; narrative belongs in typed body files.

### The tree is verb-only

**The status tree's structure is mutated only through three new verbs**, each carrying a fixed step-list that preserves the shape:

- **[`grow`](../verbs/grow.md)** — add a node; the level is inferred from the attach point (root → focus, focus → stage, stage → phase).
- **[`advance`](../verbs/advance.md)** — move a focus's lifecycle status on `status.stack.md`. `in progress → done` is Human-Lead-only.
- **[`archive`](../verbs/archive.md)** — finish a focus and relocate its subtree to `status/archive/`, so the active tree only ever holds live work. Human-Lead-invoked.

**`reshape` no longer touches the tree's structure**, and **`write-lore` fills node bodies but never creates or moves nodes.** Structure is the verbs' job; substance is `write-lore`'s. Postures gate *which surface* you touch; the status-tree verbs gate *how the tree itself* is touched — different axes, both apply. `plan` stays the posture you design under; the verbs do the writing. `mount` sets the active-mark.

### Posture and dials removed

**The four postures (chat / plan / reshape / execute) are gone, and so are the dials** (altitude / commitment), the `redial` verb, and presets. The whole "conversational register" half of `status.md` is deleted. Posture's only real job was gating *what a session may touch*; the new **track type** does that job directly, so the posture layer was pure overhead — a per-session mode-flag that, in practice, didn't reliably hold attention. The five verbs `chat`, `plan`, `reshape`, `execute`, `redial` are removed along with their skills.

### Track types

**Tracks now come in three types, and the type is the write-gate** (replacing posture):

- **Trackless** — read-only across the project, no mount, no trace. The query / "just looking" mode (a spawned session that only reads the project is a trackless session).
- **Light** *(new)* — not mounted, no branch, no record; may write **only** the journal and the backlog, as drift on trunk. **Forbidden to `ack` or `save-point`** — a home session acknowledges its drift. The frictionless way to jot a note or a to-do while the home track stays the sole commit gate. (This is the acknowledgement story a *writing* helper needs.)
- **Full** — mounted, claimed, branched; writes everything within its claim. Only full tracks mount and only full tracks carry a `tracks/` record. Claims are unchanged — disjoint-by-prefix keeps parallel full tracks from colliding.

The `track` and `journal` schemas drop their `posture` and `dials` fields.

**Creating a full track is now split from mounting one.** A new verb — **`spawn`** — creates a child track from **home**: the Human Lead and the session settle its name, claim, and focus, and `spawn` opens the record (`tracks/<name>.track.md`) and branch *without* attaching a session. [`mount`](../verbs/mount.md) becomes **attach-only** — it no longer conjures a child mid-mount; a child must be spawned first, then a (typically different) session mounts it. The child lifecycle reads cleanly as **spawn → mount → merge/abandon**, and child-track birth is a deliberate, home-managed act rather than a side effect of a write.

### The backlog

**A new `status/backlog/`** — a tree of folders and item files where work that is *not yet a focus* is annotated. Grouped freely (no positional rule, no depth cap), but under the universal index-per-folder discipline. A backlog item **graduates into a focus** via `grow`, then leaves the backlog. It is never listed in `status.stack.md` (that registers focuses). The backlog is one of the two surfaces a light track may write.

### Lazy methodology loading

**A session loads only a thin eager core at `orient`** — `project-structure.md`, `status.md`, `verbs.index.md` — and pulls the rest on demand. **Each verb and bookend declares the pillars it needs** (a *Prerequisites* line); because a session can act only through a verb/bookend chokepoint, the declaration *guarantees* the load — it is never left to the session noticing it is missing context. Indexes support ad-hoc browsing, but correctness rides on the declared prerequisites. `ai_readme.md` and `orient` are rewritten around this; `bindings.md` notes the smaller SessionStart load.

### Blueprint gains a `tooling/` branch

**Blueprint goes from three branches to four** (contracts / processes / **tooling** / mirror). `tooling/` registers the executable resources a project owns — a build script, a doc generator, an aux app — with path, invocation, and purpose. Distinct from `processes/`: a process is a checklist the AI executes by hand; a tooling entry points at something that executes for it.

### `out/` — disposable scratch

**A root-level `out/` folder, symmetric to `publish/`**, is the catch-all for writes AI-Lore must make but isn't meant to keep — generated reports, a verb's working files, the harness `/plan` scratch file. It is in no git repo (the Payload `.gitignore` excludes it, written by `init`). One hard rule keeps it honest: **nothing in `out/` is ever a source of truth — disposable by definition.**

## Migration

See [`migration-from-v0.6.1.md`](../migration-from-v0.6.1.md). The bulk is a one-time Memory reshape — build the status tree from the old `status/focus/` + `action-tree/`, write `status.stack.md`, rewrite `status.index.md` as a strict index, relocate the journal trail, retire `action-tree/`, add `blueprint/tooling/` and `out/`. The **journal files** and the **save-points ledger** are append-forward / append-only and are never touched. Tracks, dials, postures, the two-repo git contract, and the claim model are unchanged.
