## Summary

A **subtraction with teeth.** v0.4's core — the Memory model, the journal, the action tree — works; the machinery layered around it does not. v0.5 removes the machinery and keeps the core, while sharpening the parts that survive: postures are recorded with real constraints; focuses declare what kind of work they are; the blueprint grows three explicit branches; the live register is split out from Memory as a peer pillar; and acknowledgement and milestones are anchored to git commits.

The organising principle: *a standing state the session sits in becomes a verb it invokes, and the durable record is anchored where it cannot drift.*

## Changes

**Stances → dials.** The four-dial stance system is gone. v0.5 keeps the two dials that describe how the session *talks* — Altitude and Commitment — and drops the two that described what it *does* (Precision, Ownership). Behaviour is no longer set by a standing identity.

**Status split out of Memory as a peer pillar.** What v0.4 grouped under Memory is split in v0.5 into two equally-weighted pillars: **Status** (the live register — status, focus, dials, posture, focus chain mechanics) and **Memory** (the persistent record — journal, blueprint, save-points, action tree, knowledge tree). `dials.md` folds into `status.md`. The pillar split is documentation-only; status files still live on disk under `memory/status/`.

**Modes → postures with teeth.** v0.4's four modes — Reflecting, Planning, Salvaging, Executing — collapse into four postures recorded in `status`: `chat`, `plan`, `reshape`, `execute`. Each posture is a real constraint on what the session may touch (`chat` makes both repos read-only; `plan` and `reshape` make the Payload read-only; `execute` lifts it). The verbs of the same names set the value.

**Focus types — `build` and `goal`.** Every focus declares its kind. A `build` is concrete delivery against an evaluable gate, evaluated by the Human Lead at gate-check time. A `goal` is directional work against a subjective target; the Human Lead claims done by judgement, and the session's job is to deliver *and* offer opinionated critique alongside.

**Focus tracking primitive (renamed from "tracker").** Status, the active focus, and action-tree nodes are all *focus nodes* — each tracks the project's focus at a given depth. Every focus node carries the same four fields (Stack, Active child pointer, Journal trail, Gate). The active path through them is the *focus chain*. v0.4's "tracker primitive" / "tracker chain" terminology is retired.

**Blueprint structure — three branches.** Blueprint splits into `contracts/` (evergreen rules), `processes/` (repeated procedures), and `mirror/` (description of the Payload's shape, mirroring its directory tree). The flat v0.4 blueprint migrates into `contracts/`.

**Save-point as hard contract.** A save-point is **always** a git commit of both repositories. Blueprint contracts can layer additional gates above the commit minimum.

**`ack` verb and drift signal.** A new verb, [`ack`](../verbs/ack.md), commits both repos with a focused message — the lightweight cousin of `save-point`. The working tree's dirty state is the drift signal; the session surfaces it at `orient` and `close-session`. The session never self-acks — acknowledgement is always a Human Lead action.

**Verbs.** The operation set is eleven verbs — `write-lore`, `redial`, `ack`, `save-point`, `chat`, `plan`, `reshape`, `execute`, `init`, `upgrade`, `install` — plus two bookends, `orient` and `close-session`. `write-lore` is the sole path for writing Memory and carries the three golden rules and the discard guard.

**Plugins and the build system removed; methodology now placed by `init`.** AI-Lore plugins, `build-process.sh`, the `upstream/` and `dist/` staging, and the substitution pipeline are all gone. The methodology is plain text, placed into each project at `init` time: a two-line shim at the project root (`ai_readme.md`) and a verbatim copy of the pillars and verbs under `.ai-lore-<project>/process/`. No build, no template substitution — just the project name interpolated into the root shim. `upgrade` re-places the methodology when `core_version` moves.

**Bindings and `install`.** The methodology is platform-neutral plain text. Any AI: open the project, say *"read ai_readme.md"* — the shim redirects to the real entry point, the session loads the pillars. Engine bindings layer engine-native delivery on top via the `install` verb, invoked per engine (`install-claude`, `install-gemini`). `install-claude` writes a delimited block to `CLAUDE.md`, registers each verb as a skill under `.claude/skills/`, and wires SessionStart/SessionEnd hooks to the bookends. The plain-text path stays available after install — a different AI can open the same project and still operate.

**References.** A fifth term joins Project / Payload / Lore / Memory: a **Reference** is a pointer to another AI-Lore project this one consults for context. References live at `.ai-lore-<project>/references/`, one file per referenced project, carrying link metadata only (purpose, scope, target path). Read-only by contract; insights drawn from a reference go in this project's knowledge tree with `source` pointing back. Optional — emptiness is a valid state.

**Memory schema.** Every Memory file gains YAML frontmatter plus a per-type body structure, so a program — such as a companion runtime — can parse it. Human readability is unchanged.
