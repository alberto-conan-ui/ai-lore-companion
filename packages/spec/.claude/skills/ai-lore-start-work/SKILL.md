# start-work

The journey from "we should do X" to a mounted session doing X. This is the
choreography the individual cards can't carry: *when* each verb fires and what
judgement sits between them.

## When to run

- The project commits to a new piece of work — whether it arrives as a fresh idea,
  a backlog item's graduation, or a "what should we do next" conversation.

## The steps

1. **`review-backlog`** *(optional — skip when the work is already chosen)* — scan
   for an existing item covering this intent, and for neighbors that should merge
   into it. Judgement: is this new work, or work already captured?
2. **`add-new-focus`** — the commitment moment: focus_type, gate or vision, claim
   proposal. If a backlog item graduates, it is absorbed and removed here.
3. **`add-stage`** *(optional — decompose late)* — only when the work's batches are
   already visible. A focus may start bare; stages can wait for the build to reveal
   them.
4. **`mount-track`** — home if free (the common case: automatic); otherwise the
   spawn conversation belongs to [`parallel-work`](../../../.ai-lore-ai-sdlc/memory/blueprint/processes/core/parallel-work.process.md).
   First work moves the focus `draft → in progress`, no ceremony.
5. **`update-focus`** *(as the first work clarifies the plan)* — sharpen the gate
   and context while the design conversation is fresh.

## Done looks like

A registered, in-progress focus with an honest gate; a mounted track pointing at
it; the first stage (if any) active; the session expert on the chain and working.
